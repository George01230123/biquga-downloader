# AI 裁决错字（v1.3.0 新增）

> 这一页讲清楚三件事：**它做什么、不做什么、以及怎么配**。
> 最重要的前提：**默认关闭。不开就完全不会联网、不会产生任何费用。**

---

## 一、它解决什么问题

「检测错字」用的是**双源比对**：同一本书从两个源各抓一份正文，逐字对比。
两个源同时错成同一个字的概率极低，所以差异点就是"至少有一边错"的位置。

但双源比对有两个它自己解不了的死结：

| 情况 | 双源比对能做什么 | AI 能补什么 |
| --- | --- | --- |
| 两个源写法不同，但**哪个对不知道** | 只能把两个都摆出来让你自己猜 | ✅ 判断哪个对，或指出两个都不对并给建议 |
| **两个源都错成同一个字** | 连差异都看不到，检测不出来 | ❌ 补不了（没有差异就没有候选，AI 也看不到） |
| 一边错字一边漏字 | 归为"字数不一致" | ❌ 不送 AI（见下） |

**所以它是"补半个死结"，不是万能。** 报告里如实写明了这个局限。

---

## 二、为什么不让 AI 通读全文找错字

这是刻意的设计选择，不是偷懒：

1. **成本和幻觉都不可控**。整本书几百万字送进去，费用和耗时都很难预估；
   而且模型会**把正确的字也"改"掉** —— 对"校错字"来说这是灾难。
2. **候选位置已经算好了，没必要重算**。双源比对已经把"可疑位置"缩到几百处，
   直接问这几百处就行。
3. **只发差异点前后十几个字**，不发整章、不发整本。
   这既省钱，也让"内容外发"的暴露面小到可以接受 ——
   发出去的是零散片段，不是全文。

实测的量级：一本百万字的书、几百处差异，**约几万 token**。

---

## 三、只送"高可疑"的差异

站点排版差异占了报告里的大头，但它们**根本不是错字**，送了既费钱又干扰模型判断。
所以先用规则筛一遍（`AiAdjudicator.IsHighSuspicion`）：

| 送 AI | 不送 |
| --- | --- |
| 两边**长度接近**（差 ≤1） | 长度差过大（那是排版差异） |
| 差异是**汉字** | 纯标点/数字差异 |
| 差异很短（≤4 字） | 长片段（那是整段不一样） |
| 类型是 Replace（用字不同） | 多字/漏字（AI 判"该不该补一个词"很不稳，容易顺手改文风） |

已经被标成「疑似站点差异」的，一律不送。

## 四、怎么配

在主界面点 **「AI 设置」**，或者在「检测错字」跑完比对之后，程序会**主动问你**：

```
双源比对完成：有 37 处差异值得让 AI 判断哪个写法对。
预计发出约 4,012 字符（≈4,012 token）—— 只发差异点前后十几个字，不发整章。
```

**带着真实成本做选择**，而不是配完一堆参数才发现要发多少东西。

### 本地（推荐先用这个）

需要装 [Ollama](https://ollama.com/)：

```powershell
ollama pull qwen2.5:7b
```

然后程序里选「本地模型」—— 它会用 `GET /api/tags` **探测你机器上真装了的模型**，
下拉直接选，不用手打 `qwen2.5:7b` 这种容易写错的名字（少个冒号、大小写错都连不上）。

**优点**：不联网、不花钱、正文不出机器。
**代价**：需要下载几 GB 的模型；效果取决于模型大小。

### 云端

程序内置预设，选完自动填好地址与模型名：

| 预设 | 模型 | 说明 |
| --- | --- | --- |
| **智谱 GLM** | `glm-4-flash` | 有免费额度，适合"想用 AI 又不想花钱" |
| DeepSeek | `deepseek-chat` | 中文强、便宜 |
| 硅基流动 | `Qwen/Qwen2.5-7B-Instruct` | 聚合多家开源模型 |
| 商汤日日新 | `SenseChat-5` | 见下面的坑 |
| 自定义 | 自己填 | vLLM / LM Studio / one-api 中转都行 |

> ⚠️ 各家的免费额度和模型名会变，以官方控制台为准。
> ⚠️ **密钥以明文保存在 `settings.ini` 里**。这个项目零依赖、没有安全存储可用，
> 与其假装安全不如说清楚 —— 请不要把 `settings.ini` 分享给别人。

**选云端要再确认一次**（那是"内容外发"的同意步骤）：

> 即将把**差异点前后的正文片段**发送到：`https://api.deepseek.com`
> 模型：`deepseek-chat`，密钥会以**明文**保存到 `settings.ini`。确认继续吗？

### 商汤日日新的坑（实测）

**该平台对未开通的凭据返回 `403 Forbidden`**，而不是"权限不足"之类的提示。

判别方法（我实测出来的对照）：

```
有效且已开通   → 200
格式有效但无权限 → 403  {"code":7,"message":"Forbidden"}
凭据本身无效   → 401  {"code":16,"message":"Forbidden"}
```

**403 和 401 是两个不同的错**：403 说明"你这凭据格式是对的，但没权限"。
遇到 403 请去 [控制台](https://console.sensecore.cn/aistudio/management/api-key)
确认：key 是否开通了日日新的调用权限、账户是否欠费、是否有 IP 白名单。

> 如果是 **IP 白名单**，那你在本地能通、别的机器永远通不了。

## 五、报告里长什么样

跑完 AI 之后，`错字检测报告.txt` **最前面**会多一段「待改清单」——
这是你真正要改的地方，埋在几百条差异里等于没找到：

```
★ 待改清单（AI 判定这些位置的主源写法有问题）　共 3 处
------------------------------------------------------------
第一章 @1247　「现」→「現」　（用字正确）
第二章 @88　「面条」→「面條」　（简体写法）
（要精确替换，用同目录的 错字检测报告.csv 按「位置」列定位）
```

每条差异下面也会多一行：

```
  【AI】主源可能错（正确写法见报告里的对照源列）　理由：繁简用字
```

`错字检测报告.csv` 新增两列：`AI结论`、`AI建议`，方便按「位置」列定位替换。

### AI 的三种结论

| 结论 | 含义 | 你要做什么 |
| --- | --- | --- |
| 主源正确 | 你这份没问题 | 不用管 |
| **主源错** | 对照源的写法才对 | **去改**（进「待改清单」） |
| 两边都不对 | 并给出建议写法 | 看一眼建议合不合理再改 |
| 判断不了 | 上下文不够，模型拒答 | 人工看 |

**AI 也会判断错，重要的地方请自己复核。** 提示词里明确要求它在拿不准时
必须回答"判断不了"而不是猜 —— 但模型不一定每次都听话。

## 六、接口路径自适应

各家的 `base_url` 形状没有统一标准，而且我每见一家就踩一次坑：

| 平台 | base_url | 坑 |
| --- | --- | --- |
| OpenAI / DeepSeek | `https://api.deepseek.com` | 要补 `/v1` |
| 智谱 | `.../api/paas/v4` | 带版本段但**不是** v1，补 `/v1` 就 404 |
| 商汤日日新 | `.../compatible-mode/v2` | 同上，形态又是另一种 |

所以程序**不再替你猜 URL**，改成**按顺序试一串候选**：

1. **你填的原样** —— 从官方文档复制的完整端点，原样就是对的，不能被程序改坏
2. 补 `/chat/completions`
3. 补 `/v1/chat/completions`（结尾已经是 `/v<数字>` 时跳过，否则会成 `/v4/v1/...`）

哪条通了就记住，后面几批复用 —— 否则每批都从头试，请求数要翻三倍。

**关键：只在"路径不对"时换，鉴权失败绝不换。**

```
404 / NOT_FOUND / no Route matched  → 换下一个候选
401 / 403 / 超时                     → 立刻停手
```

理由：403 是账户权限问题，换十个路径还是 403 —— 既白等，又可能拿错误凭据
反复敲门而**把自己的 IP 打成可疑流量**。（商汤那次实测就是一路 403。）

## 七、AI 挂了会不会影响下载

**不会。** `AiAdjudicator.Run` 承诺**不抛异常**，所有失败都降级成"未裁决"：

- 模型没启动 / 名写错 / 网断了 / 超时 → 记进日志，**报告照常生成**
- 模型回答格式不对 → 解析不出来的那几条算"未裁决"，不影响其它条
- 用户中途取消 → 立刻停，已裁决的部分保留

AI 是锦上添花，不能变成新的失败点。

## 八、验证到什么程度（如实说明）

| 验证手段 | 覆盖什么 | 状态 |
| --- | --- | --- |
| 离线单测 | 可疑度筛选、成本估算、请求体/URL 构造、**响应解析**（含各种脏输出） | 1014 项全绿 |
| `_aimock openai/ollama` | 真起一个假服务，走**完整 HTTP**，验证裁决落到报告 | 19/19 ×2 |
| `_aimock err` | 模型名写错时的优雅降级 | 9/9 |
| `_aimock fallback` | 6 种 base_url 形状的路径自适应 | 36/36 |
| **真实模型** | 模型是否严格按输出格式回答 | ⚠️ **还没验过** |

**"响应解析"测得特别细**，因为小模型（尤其本地 7B）经常不照格式回答：
多写解释、用全角竖线、加 markdown 列表符号、少给字段、夹废话。
下面是实测要容忍的输入形态：

```
1|A|用字正确|                    ← 标准
1｜A｜理由                        ← 全角竖线（中文输入法下常见）
- 1|A|带列表符号                  ← markdown 列表符
2|A（写法A正确）|x                ← 结论带括号说明
好的，我来分析：\n\n1|A|正确      ← 夹在废话里
```

解析器对上面每种都能正确取到结论；取不到的算"未裁决"，绝不因为格式问题丢掉整批。

### 还没验证的那一项

本机没有 Ollama、也没有可用的云端凭据（商汤那个 key 被服务端 403 拒），
所以**没有对真实模型跑过**。

管道（HTTP、请求体、解析、写回、报告、CSV）都验过了，但
**"真实模型是否守输出格式"只有真跑一次才知道**。

所以界面上有 **「测试连接」** 按钮：它只发一条最简单的裁决请求，
然后把模型的**原始输出**显示给你。**跑整本书之前先点它** ——
那一步就能看出模型听不听话。

如果模型不守格式，加固方向（按见效顺序）：
1. 提示词加一个 few-shot 示例（通常加上就老实了）
2. 把 batch size 降到 1（一次只问一条，格式压力最小）
3. 换一个更大的模型

## 九、为什么不做"登录 DeepSeek 免费网页对话"

这个需求被提过，**没做**，因为它会破掉项目一直守的边界。

`chat.deepseek.com` 是**网页对话界面，不是 API**。程序化用它只有两条路：

1. **内嵌浏览器自动登录 + 伪装成浏览器调内部接口**
2. 让用户手动贴 session cookie

第 1 条正是 `docs/同类工具调研.md` 里明确列为**不做**的那一类
（绕过访问控制 + 和站点打军备竞赛），而且它比抓网页更脆：
DeepSeek 一改前端就全废，还可能触发风控封号。

第 2 条技术上可行，但**仍然是在用"登录态"调非公开接口**，cookie 还会过期。

**替代方案**：智谱 `glm-4-flash` **有免费额度**，走标准 API、合规、
不用绕任何东西 —— 这才是"想用 AI 又不想花钱"的正当路径。
所以它被排在云端预设的第一位。

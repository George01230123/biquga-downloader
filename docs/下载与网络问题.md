# 下载与网络问题（github.com 打不开时怎么办）

国内网络访问 `github.com` 经常不稳定：可能一会儿通、一会儿超时
（本项目开发期间实测断过两次，每次几分钟），但 `api.github.com` 往往一直是通的。

本文列出**实测过**的几种下载方式，按推荐顺序排。

---

## 方式 1：正常点 Release（首选）

打开 https://github.com/George01230123/biquga-downloader/releases/latest
在 Assets 里点 `novel-downloader-v1.0.1-win64.zip` 即可。

实测：`http=200`，56,219 字节，0.5~0.9 秒。

---

## 方式 2：github.com 打不开，但 api.github.com 能通 → 跑这段 PowerShell

复制粘贴到 PowerShell 里执行（**不用改任何东西**，会自动找最新版附件）：

```powershell
$base = 'https://api.github.com/repos/George01230123/biquga-downloader'
$rel  = Invoke-RestMethod "$base/releases/latest" -Headers @{ 'User-Agent' = 'ps' }
$asset = $rel.assets[0]
"找到附件：$($asset.name)  $($asset.size) 字节"
Invoke-WebRequest $asset.url -Headers @{ 'User-Agent' = 'ps'; 'Accept' = 'application/octet-stream' } `
  -OutFile "$env:USERPROFILE\Downloads\novel-downloader.zip"
"已下载到：$env:USERPROFILE\Downloads\novel-downloader.zip"
```

实测输出：

```
找到附件：novel-downloader-v1.0.1-win64.zip  56219 字节
已下载到：C:\Users\<你>\Downloads\novel-downloader.zip
```

> Windows 自带的 PowerShell 5.1 能跑，不需要装任何东西。

---

## 方式 3：用 curl（命令行党）

```powershell
# 第一步：查最新版的附件 ID（看输出里的 "id": 数字）
curl.exe -s https://api.github.com/repos/George01230123/biquga-downloader/releases/latest

# 第二步：用 ID 下载（<ID> 换成上一步看到的数字）
curl.exe -L -H "Accept: application/octet-stream" -o novel-downloader.zip `
  https://api.github.com/repos/George01230123/biquga-downloader/releases/assets/<ID>
```

实测：`http=200`，56,219 字节，文件头 `50 4B 03 04`（正常 zip）。

---

## ⚠️ 一个常见坑：直接把 api 链接粘到浏览器里，只能看到一段 JSON

GitHub 的附件接口是**内容协商**的：

| 请求方 | Accept 头 | 返回 |
| --- | --- | --- |
| 浏览器 | `text/html,...` | ❗ **一段 JSON 元信息**（`{"url":...,"id":...,"name":...}`），不是文件 |
| curl / PowerShell / 下载工具 | `application/octet-stream` | ✅ 文件本体 |

所以：

- `https://api.github.com/.../releases/assets/<ID>` 这个地址**不能**直接双击/粘到浏览器地址栏当下载链接用；
- 想用浏览器就直接用 Release 页面上的链接；
- 想走 API 就必须按方式 2 或方式 3 带上 `Accept: application/octet-stream`。

（另外 `.../assets/<ID>?download=1` 这种写法实测返回 **404**，不用试。）

## 其它可能的原因

如果三种方式都不行，先确认不是本地问题：

```powershell
curl.exe -s -o NUL -w "%{http_code}`n" --max-time 15 https://api.github.com     # 期望 200
curl.exe -s -o NUL -w "%{http_code}`n" --max-time 15 https://github.com         # 期望 200
Resolve-DnsName github.com -Type A                                              # 看解析出来的 IP 是否正常
```

常见情况：

- `github.com` 返回 `000` + `Failed to connect ... after Ns` = 连接被阻断/超时，等几分钟重试或换网络；
- 两个域名都不通 = 代理配置问题（检查 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量与系统代理）；
- 能打开网页但下载中断 = 用了下载工具的多线程分段，改单线程或改用方式 2。

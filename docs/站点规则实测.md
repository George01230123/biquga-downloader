# 站点规则实测记录

本文记录 `src/Common/SiteRules.cs` 里每条规则的**实测依据**。
规则不是照着别人的文件抄的 —— 每一条正则都对着真实抓下来的 HTML 校准过，
并且记下当时的实测数字。**没有实测依据的站点不写进来。**

探针用法（联网，返回 0 = 全通）：

```
dist\_liveprobe.exe sites            用规则自带的 KnownTitles 跑全链路
dist\_liveprobe.exe sites 剑来        指定关键词
```

## 一、结论总览（2026-10-14 实测，本机 curl）

在 so-novel 的 11 个书源里，**只有 2 个能走完「搜索 → 目录 → 正文」并拿到可读正文**。

| 站点 | Key | 搜索 | 目录 | 正文单章 | 综合分 | 判定 |
| --- | --- | --- | --- | --- | --- | --- |
| **笔尖中文** | `xbiquwk` | 500 ms | **647 ms / 1308 章** | 608 ms / 12379 汉字 | **1755 ms** | 接入 |
| **笔趣阁365** | `biquge365` | 896 ms | 1734 ms / 300 章 | 707 ms / 1787 汉字 | 3337 ms | 接入（搜索不稳） |

> 综合分 = 搜索 + 目录 + 正文单章，越小越快。「自动选最快站点」就是按它排的。
>
> 笔尖中文的目录**一页给全**（1308 章 / 647 ms）。作为对比，笔趣阁 PC 版走
> 772 页串行链要约 10 分钟 —— 这是本次接入最实际的收益。

## 三、逐站校准记录

### 3.1 笔尖中文 `xbiquwk`

**域名注意**：so-novel 的规则写的是 `xbiquzw.net`，实际已跳转到 `xbiquwk.com`。
搜索端点仍是 `/modules/article/search.php`。

| 字段 | 实测依据 |
| --- | --- |
| `SearchUrl` | `POST http://www.xbiquwk.com/modules/article/search.php`，表单 `searchkey=关键词` |
| `BookLinkPatterns` | 搜索结果是表格：`<td class="odd"><a href="/1_1245/">剑来</a></td>`。实测 50 条结果 |
| `BookTitlePattern` 等 | 全在 `og:` 元信息（`og:novel:book_name` / `og:novel:author` / `og:description` / `og:image`）——比抓 `#info` 的 DOM 稳 |
| `TocBlockPattern` | `<div id="list">` |
| `TocLinkPattern` | `<dd><a href="603316.html" title="...">标题</a></dd>`。**链接是扁平相对地址**（`603316.html`，不是 `/1_1245/603316.html`），所以必须相对详情页解析 |
| `ContentPattern` | `<div id="content">` |
| `ContentStripPattern` | 无 —— 实测该块没有广告行（正文直接从「二月二，龙抬头」开始） |

**实测目录规模**：《剑来》详情页 1317 个链接、**1308 章**。

**干扰链接**（实测详情页上就有 7 个，必须不被当成章节）：

```
http://www.xbiquwk.com/list/1_1.html                  ← 分类页导航
http://www.xbiquwk.com/paihangbang_allvisit/1.html    ← 排行榜
```

这就是 `TocBlockPattern`（先框住 `#list` 容器）存在的理由。

### 3.2 笔趣阁365 `biquge365`

**★ 最大的坑：详情页只有最近几章，不是完整目录。**

实测 `/book/417022/` 的 `<ul class="newchapter">` 只有 **21 个**章节链接，
而这本书实际有 **300 章**（`og:novel:latest_chapter_name` = 第300章 暗杀）。
完整目录在**另一个地址**：

```
/book/417022/          → 21 章（最近）      ← 详情页
/newbook/417022/       → 300 章（完整）     ← 目录页，<ul class="info">
```

`/chapter/417022/685327301.html` 是「开始阅读」，出现在 `div.gongneng` 里 —— 见下。

所以规则里必须用 `TocUrlTemplate = "https://www.biquge365.net/newbook/%i/"`
（`%i` = 路径里第一段数字，`/book/417022/` → `417022`）。
**只靠详情页会静默地少抓 279 章。**

| 字段 | 实测依据 |
| --- | --- |
| `SearchUrl` | `POST https://www.biquge365.net/s.php`，表单 `type=articlename&s=关键词` |
| `SearchIsResultPattern` | 结果页有 `搜索"..."的结果`。**站点对搜索有 15 秒间隔限制**，太快会返回该提示的空页 |
| `BookLinkPatterns` | `<span class="name"><a href="/book/417022/" title="...">书名</a></span>` |
| `TocUrlTemplate` | 见上，`/newbook/%i/` |
| `TocBlockPattern` | `<ul class='info'>` |
| `TocLinkPattern` | `<li><a href="/chapter/..." title="第1章 本书设定">第1章 本书设定</a></li>`，**必须要求 `title=` 属性** |
| `ContentPattern` | `<div id="txt">` |
| `ContentStripPattern` | 首行水印「一秒记住【笔趣阁】biquge365.net，更新快，无弹窗！」 |

**两个必须记住的实测细节：**

1. **`ul.info` 里 300 个章节链接全部带 `title` 属性** —— 所以 `TocLinkPattern`
   里加 `\btitle=` 约束是安全的，而这条约束正好挡住下面那个导航链接。
2. **稳定性**：搜索**时好时坏**（多次实测里出现过 0 条结果，就是撞上 15 秒限流）。
   所以它的综合分会被拉高，自动选站时自然排在笔尖中文后面 —— 这是设计意图。

## 四、踩过的坑（给后续维护者）

### 4.1 用 Python 验证正则，会得出「没问题」的错误结论

抓目录时旧实现是这么取章节标题的：

```csharp
// 旧写法（有 bug）
var tm = Regex.Match(html, "<a[^>]*href=\"\\s*" + Regex.Escape(href)
    + "\\s*\"[^>]*>([\\s\\S]{0,160}?)</a>", RegexOptions.IgnoreCase);
```

`[^>]*` 允许跨过 `>`，所以它常常匹配到**前一个链接**的文字；而页面上更早的位置
如果有一条**指向同一 URL 的导航链接**，那一条会先被匹到。
笔趣阁365 的 `/newbook/` 页恰好如此：`div.gongneng` 里的「开始阅读」指向第 1 章，
于是**目录第一项的标题变成了「开始阅读」**。

**最阴的地方**：同一个正则在 Python 里不会这样匹配。我拿 Python 验证时得到的是
「第一条是『第1章 本书设定』，没问题」—— 差点就这么放过去了。

所以现在的做法是：**标题只从 `m` 自己的匹配文本里取**，而且规则直接用第二个
捕获组给出标题。逻辑上不可能取错。

### 4.2 别拿 `CoverFetcher.Absolutize` 拼章节地址

那个函数的语义是「相对**站点根**」（为封面写的）：
所有不以 `/` 开头的地址都拼到域名后面，于是笔尖中文的
`603316.html` 会变成 `/603316.html`（**丢掉 `/1_1245/` 这一层**），
而且它会把 `../` 直接吃掉。

章节地址拼错**不会报错**，只会 404 或抓到别的页 —— 最难查的那种。
`RuleSite` 因此自己实现了标准的页面相对解析（`ResolveUrl`）。

### 4.3 `HttpBatch` 没有 `--compressed`，但实测是安全的

笔尖中文的详情页（约 200 KB 未压缩）在客户端**声明支持 gzip** 时会压缩返回。
`Http.FetchWithCurl` 带了 `--compressed`（会解压），而 `HttpBatch` **没带**
（就不会被压缩，拿到的是明文）——实测两条路都能拿到正确内容。

### 4.4 站点对搜索有间隔限制

笔趣阁365 是 15 秒。撞上限流时站点返回一个空结果页而**不是错误码**，
所以规则里用 `SearchIsResultPattern` 确认「这一页确实是结果页」，
避免把空页当成「真的没有这本书」。

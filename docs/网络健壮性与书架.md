# 网络健壮性 / 书架 / 批量下载（v1.1.0 新增）

这一批功能都是**看了同类工具之后补的**（调研见 `docs/同类工具调研.md`），
分三类：让下载更不容易失败、把已经抓到的信息用起来、以及省事的批量操作。

---

## 一、请求退避与限速自适应

### 为什么改

老实现的重试是**固定 500ms × 次数**。这对"网络抖了一下"有效，对**站点限流完全无效** ——
限流惩罚的正是"立刻重试"这个行为，退避不够只会让冷却时间不断刷新。

更麻烦的是限流**不一定会给状态码**。实测过的两种情况（引自 `docs/同类工具调研.md` 4.1）：

- 零点小说：并发 1 也会被限流，正文被替换成「访问太频繁了，奴家受不了啦，请30秒过后刷新重试！！！」
- 新天禧小说：下载过快会导致**章节内容为空**

这两种都是 **HTTP 200 + 内容不对**，光判断状态码发现不了。

### 现在的做法

| 机制 | 说明 |
| --- | --- |
| **指数退避 + 抖动** | 普通失败 500ms → 1s → 2s…；限流失败从 **2s** 起步，封顶 `MaxBackoffMs`（默认 20s）。抖动避免多个线程退避后同时回来（惊群） |
| **状态码识别** | curl 后端带 `-w "%{http_code}"` 取真实状态码；`429 / 503 / 403` 直接判为限流并走重退避 |
| **正文特征识别** | 短文本（< 2000 字）里出现「访问太频繁」「请稍后重试」「too many requests」等 → 判为限流。**长文本一律不匹配**，避免把小说正文误判 |
| **并发自适应** | `Http.AdaptiveWorkers()`：每命中 2 次限流减 1 线程，最低 1；成功一次回一点。站点限流时"降并发"比"加重试"有用得多 |
| **每本书重置计数** | `Http.ResetThrottle()` 在每本书开始时调用，免得上一本被限流的账算到这一本头上 |

**关键设计**：限流抛的是 `Http.ThrottledException`，它**不触发"换后端重试"**
（从 curl 换到 .NET 解决不了限流，只会白白多打一次站点）。

### 离线断言

`TestRateLimitMarkers`：短警告文本会被认出来、长正文不参与匹配、特征词表里没有空串
（空串会让 `IndexOf("")` 恒为 0 → **一切都被判成限流**）、自适应并发的边界。

## 二、代理与 Cookie

```ini
[biquga-m]
proxy=socks5://127.0.0.1:1080
cookie=你从浏览器复制来的 Cookie
```

- **proxy**：支持 `http://` / `https://` / `socks5://`，也可以只写 `127.0.0.1:7890`（按 http 处理）。
  实现上直接交给 `curl.exe -x`，所以 **SOCKS 也能用**，不用自己实现协议。
  > .NET 原生后端**不支持 SOCKS**（框架限制）。这种情况会静默忽略代理而不是抛异常 ——
  > 否则用户开了 SOCKS 反而连直连都用不了了。
- **cookie**：整串原样发送。用途是"让站点认得你"（有些站的详情/封面接口要登录态才给完整数据），
  **不是绕过权限** —— 请只填自己账号的 Cookie。

`SiteProfileStore.Apply()` 里**空字符串也要写回去**，否则上一本书设的代理会残留到这一本。

## 三、封面

### 之前的状态

`EpubWriter` **早就支持封面**（`coverBytes` / `coverExt` 参数齐全、`OEBPS/images/cover.*` + `cover.xhtml` 都写好了），
但 `MainForm` 调用时一直传的是 `null, null` —— 缺的从来不是"写 EPUB 的能力"，而是"把图抓下来"这一步。

### 现在的做法

1. **解析**：详情页的 `og:image` 优先，退回 `og:novel:image`，再退回第一张像封面的 `<img>`（BiqugaMobile / Biquga PC）；
   番茄取 `page.thumbUrl`。相对地址统一补成绝对地址（`CoverFetcher.Absolutize`）。
2. **抓取时机**：在 `DownloadRunner.Run()` 里、正文下载之前。
   为什么必须在这里 —— 站点普遍有**防盗链**，请求要带详情页当 `Referer`，而那个上下文只有加载目录时才有。
3. **落地**：书目录下的 `封面.jpg/.png/...`。**导出 EPUB 时直接读本地文件，不联网**，
   和"已下载的正文不依赖网络"这条既有设计保持一致。
4. **格式识别按魔术字节**，不信 URL 后缀（很多站的封面 URL 是 `...?id=123` 或给错扩展名）。
   认不出来就**不出封面**，而不是往 EPUB 里塞一张坏图。
5. **失败绝不影响正文**：所有异常都吞掉、只记一行日志。一张图不值得让整本书失败。

另外：先写 `.tmp` 再改名。否则下载中途被杀会留下半张图，而 `Find()` 会把半张图
当成"已经抓过"，之后**永远修不好**。

## 四、分卷结构

### 之前的状态

`ChapterInfo.IsVolume` 字段有、缓存也存了，但 `EpubWriter` / `MarkdownWriter` 里是
`if (c.IsVolume) continue;` —— **番茄的分卷信息白抓了**。

### 现在的做法

难点在于：导出时传进来的 `chapters` 通常是"已经有正文的那些章"，**分卷行早被过滤掉了**，
单看这个列表推不出卷边界。所以由调用方（`MainForm.VolumeTitlesFor`）回原始目录反推出
"第 i 章属于哪一卷"，再传给写出器。

- **EPUB**：nav 里按卷嵌套。卷用 `<span>`（EPUB3 里表示"不可跳转的分组节点"，阅读器会当层级标题显示），
  不给卷单独生成页面 —— 那样翻页时会多出一页只有标题的空白。
- **Markdown**：卷用 `##`，章节**整体降一级**成 `###`（否则"卷"和"章"都是 `##` 看不出层级），
  front matter 里多一个 `volumes: N`。

**没有分卷信息时输出必须和以前逐字节一致**（不能给没分卷的书凭空多出层级）——
这条有断言守着（`TestVolumeGrouping`）。

## 五、字数统计与阅读时长

`BookStats`：汉字按字符 1:1（和起点/番茄的通行口径一致，不是按词），
非汉字的可见字符也计入，**空白字符不计**。阅读速度取 **350 字/分钟**（偏保守）。

- 代理对（emoji / 扩展区汉字）算**一个字**，不拆成两个 —— 长书累积起来误差可观。
- 番茄 `page.wordNumber` 给的站点字数会**单独标注**为「站点标称」，
  因为它和「已下载字数」不是一回事（缺章的书站点字数会虚高）。

## 六、本地书架（一键追更）

「更新新章节」本来就有，但**前提是当前已经载入了那本书的目录** ——
想追更就得重新搜书名、再等一次目录。而追更恰恰是高频操作（每天/每周一次）。

书架把 `(站点, 书籍标识, 标题)` 存到 exe 同目录的 `书架.json`（UTF-8 带 BOM，可手改），
让"打开工具 → 点书架 → 点更新"成为可能。

- **所有下载路径最后都会走到 `ReportDownloadFinished`**，所以记书架放在那一个地方就够，
  不用每个入口都加一遍。
- 追更时**不按书名搜**（站点上可能有重名书，第一条未必是这本），
  优先用记录里的详情页地址 / book_id 直接载入。
- 存储用**手写 JSON**（零依赖原则）：结构是本项目自己写出去的，格式完全可控。

> 开发时这里抓到一个真 bug：`chapters` 写成**裸数字**（`"chapters": 1067`），
> 而读取用的 `Str()` 只匹配带引号的值 → 永远读到 0。
> 修法是加一个独立的 `Num()`，并且**必须是独立方法**（顺手用 `Str()` 会再犯一次）。
> 这条有断言守着。

## 七、任务队列（批量下载）

「任务队列」里每行一本，依次下载。设计上刻意复用主窗口的逻辑（`MainForm.RunQueue`），
**不另写一套下载** —— 项目既有原则是"界面 / 命令行自测走同一套 DownloadRunner"
（见 `docs/架构.md`），队列再写一套必然出现"队列下出来的和手动下的不一样"。

- **单本失败不影响后面的书**（catch 住继续）—— 这是挂机场景的硬要求：
  睡前排 5 本，不能因为第 2 本站点抽风就整晚只下了一本。
- 已有章节自动跳过（复用断点续传语义），**重复排同一本不会重头再下**。
- 支持行首站点前缀：`番茄：书名` / `biquga：书名`。
- 支持直接粘地址（`https://www.biquga.com/10_10333/`、番茄 `book_id`）—— 书架的追更走的就是这条路，
  所以队列必须有"按地址直接载入"的分支，不能一律去搜索。
- **关窗口 = 请求停止**（当前这本下完就停）。用 `FormClosing` 而不是按钮点击，
  这样 ×、Alt+F4、Esc 三条路都能停。
  > 这里有个容易写错的地方：点「开始」后程序自己 `Close()` 也会触发 `FormClosing`，
  > 如果不加 `_submitted` 标记区分，队列会被**当场取消**。

## 八、检查更新

只做一件事：**告诉你有没有新版本，并把下载页地址显示出来**。

明确不做的：**不自动下载、不自动替换自己**。so-novel 的 `auto-update` 默认就是关的 ——
"程序把自己换掉"一旦出错，用户连回滚的界面都没有。

- **不主动联网**：只有点了按钮才发请求。工具的主业是下载小说，
  不该在启动时偷偷连 GitHub（国内经常连不上，会让启动变慢甚至卡住）。
- 走 `api.github.com` 而不是 `github.com`：README 里实测过国内 github.com 会断，api 通常还通。
- 单独开 `Http.GetForApi()` 是因为 **api.github.com 会拒绝没有 User-Agent 的请求（403）**，
  而且要求 `Accept` 带版本号。走普通 `Request` 的话，用户只要把站点 UA 清空就会莫名 403。
- **明确区分"没更新"和"检查失败"**：网络不通时说"检查失败"，
  绝不说"已是最新" —— 后者是在撒谎。
- 版本比较用 `System.Version` 而不是字符串：`"1.0.10"` 按字符串比会**小于** `"1.0.9"`。

## 九、繁简转换（输出繁体）

勾上界面上的 **「输出繁体」**（或 `settings.ini` 里 `OutputTraditional=true`），
导出就是繁体。转换在**本地**完成，不联网。

- 实现：`src/Common/ZhConvert.cs`，**内置映射表**（两个等长字符串常量 + 静态构造函数建字典），
  不引外部词库文件 —— 这个项目刻意不分发任何第三方数据文件。
- 处理了若干**一对多**的字，用**词级例外**先于字级替换：
  `头发→頭髮`、`发型→髮型`、`理发→理髮`，而单独的 `发→發`；
  `皇后` 保持 `后`，`后来→後來`；`公里`/`里程` 保持 `里`，其余 `里→裡`。
  完整上下文转换超出范围，字表是默认行为（代码注释里写明了）。
- 转换点在 `DownloadRunner.FetchInto`（拿到正文之后、长度判断之前），
  **不是**只在写 txt 时转 —— 因为「导出 EPUB / Markdown」直接用内存里的 `c.Text`，
  只在写盘时转会出现"txt 是繁体、epub 是简体"这种自相矛盾的结果。
- **幂等安全**：表里没有的字原样通过（输入是小说正文，不能因为转换丢字）。

**三者缺一不可**，各自都漏过真 bug：

`_e2e` 全绿时每一次网络请求都是失败的（离线根本不发请求）；

> `_e2e.exe` 加上去当场就把它抓出来了。这类"零件都对、成品是坏的"问题，
> 只能靠**检查成品本身**发现。
> 现在这两组断言都做过**故障注入验证**：把坏逻辑塞回去，11 条单测 + 3 条 E2E 会立刻变红。

## 十一、联网实测发现的三个 bug（离线单测抓不到的那类）

这一批功能做完后跑了**真实站点**，抓出三个离线测试结构上发现不了的 bug。
三个都记在这里，因为它们各自的"为什么没被抓到"比 bug 本身更有价值。

### 11.1 `> 文件` 让每一次请求都失败（最严重）

为了让 HTTP 状态码落到单独文件，`FetchWithCurl` 在 curl 命令行末尾拼了：

```
... -w "%{http_code}" "https://..." > "C:\...\code.txt"
```

**但 `UseShellExecute = false` 时 `ProcessStartInfo` 是直接启动 `curl.exe`、不经过 cmd.exe**，
所以 `>` 从来没被当成重定向，而是被当成 curl 的一个参数 →
**每一次请求都返回 curl 退出码 3（URL 格式错误）**，整个程序完全不能用。

而 **691 条离线单测全绿**。为什么？因为离线测试**不发请求** ——
`ParseHttpCode` / `LooksRateLimited` 这些都是纯函数，把它们的输入喂对了就通过，
没有任何一条断言会去检查"curl 的命令行长什么样"。

修法：去掉 shell 重定向，`-w` 的输出本来就在 stdout 里，用
`p.StandardOutput.ReadToEnd()` 接住即可（响应体由 `-o` 写文件，两者不冲突）。
新增 `Http.ParseHttpCode(stdout)`，并对**重定向拼接**（实测见过 `"200000000"`）做容错。
`TestParseHttpCode` 现在有 16 条断言。

> **教训**：测试的"输入"如果是自己构造的，就永远测不到"输入本身是错的"。
> 必须有一条断言真的把请求发出去。

### 11.2 番茄的封面字段名猜错了

封面选择器是"按站点惯例"写的（`thumbUrl` / `audioThumbUrl` / `coverUrl`），
**没有访问过真实页面**。实测番茄详情页里真正的字段是 **`thumbUri`**，
上面那几个一个都不命中 —— 也就是说番茄的封面**从来就没抓到过**。

顺带补上一课：`wordNumber` 在 JSON 里是**数字**（`"wordNumber":2120892`），
而 `GetStr()` 走的是 `Convert.ToString()`，所以它是能读出来的 ——
但当时探针读到 0，原因是**命中了旧的目录缓存**，而缓存里没有这两个新字段（见 11.3）。
排查时先怀疑"字段名/类型"，实际是"缓存把新字段吃掉了"，值得记一笔。

### 11.3 目录缓存把新字段吃掉了

`BookInfo` 加了 `CoverUrl` / `WordCount` 之后，`DirCache.CachedBook` **没有跟着加**。
后果：**第一次下载有封面，第二次（走目录缓存）封面就没了**，
而且没有任何报错 —— 封面只是悄悄消失。

修法：给 `CachedBook` 补上两个字段（老缓存文件反序列化后是 null/0，安全降级）。
新增 `TestDirCacheRoundTrip`（13 条断言）专门守"字段漏存"这类问题。

### 11.4 还有一个"我以为错了、其实代码是对的"

探针一度报"Markdown 章节数不对（25 vs 24）"。查下来是**探针自己数错了**：
`## 目录` 也是一个 H2，和章节标题同级，所以 H2 数是 25 而章节数是 24。
**代码没问题，断言写错了** —— 改成数锚点 `<a id="ch` 就对了。

> 这一条也有价值：探针报红时，**先确认是产品错了还是探针错了**，
> 不要顺着错的断言去"修"本来正确的代码。

## 十二、v1.2.0：站点探活 / 错字检测 / 队列持久化

### 12.1 站点探活与自动降级

**痛点来自实测**：`m.biquga.com` 被 CDN 按 SNI 拒掉 TLS 握手时，界面只显示
`curl 退出码 35`。用户既不知道原因，更不知道**换个站点就能用**。

现在有三层：

| 层 | 做什么 |
| --- | --- |
| `NetDiag.Classify` | 按 curl 退出码把错误归因成人话（6=DNS、7=连不上、28=超时、**35=HTTPS 握手被站点拒绝**…），并给出**可照做的建议**。归不出来就返回空，**绝不瞎猜** —— 猜错会把人带偏 |
| `IProbeable` | 三个站点各自实现探活（各发 1 个请求）。启动后在后台跑，把不可用的标注在下拉框里 |
| `EnsureSiteUsable` | 载入目录前检查当前站点；不可用就提示并**可直接切到另一个源** |

两个刻意的设计决定：

- **探活不改变用户的选择，只标注**。自动改选择会让人困惑（"我明明选了移动版，怎么自己变了"）。
- **探活失败不算程序失败**。站点不通是站点的事，探针只要"能正确报出原因"就算工作正常。

顺带修了一个让归因失效的 bug：curl 失败后会回退到 .NET 后端，
而回退失败时**原来的 curl 错误被覆盖**成了笼统的"连接被意外关闭"，
于是探活只能报出"请求失败"。现在两边的错误都保留。

> 另一个被**实测证伪**的想法：我原本想"移动版不可用时自动改用 `www` 域名"，
> 因为 `www.biquga.com/{dir}/dindex_1.html` 确实返回 200。
> 但实测那是 **PC 版**的页面（22KB / 8 页 / 只解析出 2 个链接），
> 不是移动版"每页 100 章"的结构 —— 换域名救不了移动版的快速路径。
> 所以正确做法是**换站点**，这条也写进了用户可见的建议里。

### 12.2 错字检测（双源比对）

**思路**：同一本书从**两个不同的源**各取一份正文，逐字对比。
两个源同时错成同一个字的概率极低，所以差异点就是"至少有一边错"的位置。

**为什么不做"字形相近"的启发式**：那种方法只能标出"可疑"，无法回答"哪个字对"，
而且中文形近字表本身就有大量误报。双源比对给出的是**带对照的确定差异**，可判断、可核对。

实现要点：

- **最短编辑脚本**用经典 LCS 动态规划手写（几十行）。这个项目坚持零第三方依赖，
  而章节正文只有几 KB，用不着引 diff 库。
- **比对前先归一化空白**：两个源对空行、全角空格的处理都不一样，
  不归一化的话每段空行都会被报成一处差异，报告直接没法看。
- **长度差过大的章节标成"疑似站点差异"**，不逐字报。否则一边有广告、一边缺章的书会被刷爆。
- **单章差异数封顶** `MaxDiffsPerChapter = 200`。
- 输出 `错字检测报告.txt`（给人读，按"最可能是错字/多字/漏字"分三组）
  和 `错字检测报告.csv`（给 Excel 过筛）。

**如实写进报告和界面的局限**（不能让用户以为这是万能的）：

- 两个源都错同一个字 → **检测不出来**（只能靠第三个源或人工）
- 一边错字、另一边漏字 → 会报成差异，但归类为"字数不一致"
- 站点自己插入的广告 → 会报成差异（已用同一套 TextCleaner 尽量洗净）

### 12.3 繁体开关改成"导出时生效"

勾选框原来只在**下载时**生效（`DownloadRunner` 写盘前转换），
所以对**已经下载好的书**它是死的 —— 用户勾上再导出，出来的还是简体，想换繁体只能重下一遍。

现在导出路径上也转一次（`ChaptersForExport`）：勾上就转换后导出，不勾就按文件原样导出。
转换的是**副本**，不动内存里的原正文。

### 12.4 任务队列持久化

队列是"睡前排 5 本"的用法，而对话框一关内容就没了 —— 误点关闭或程序崩一次，排好的队全白费。
现在关闭时自动写 `队列.json`，下次打开队列窗口自动带回。

两个细节：**点「开始」后的自动关闭不存**（否则下次打开又看到一份已经下完的清单），
而且开始跑之后就把文件清掉。

### 12.5 书架：搜索 / 排序 / 一键检查更新

- **搜索框**：书名或作者含关键词即命中（书多了靠滚动找很难受）
- **「已下载章数」列**：直接数 txt 里的章节锚点。
  原来的"章数"列其实是**上次载入目录时**的目录长度，和"这本实际下了多少章"不是一回事，
  很容易被误读 —— 现在两列分开显示（`已下载章数` / `目录章数`）
- **「检查所有更新」**：逐本重新载入目录，对比两个章数，列出哪些书有新章节。
  **只检查不下载**，走目录缓存所以很快

### 12.6 下载前的磁盘空间检查

一本 2000 章的书正文约 20MB，加缓存和 EPUB 很容易吃掉几个 G。
而**磁盘写满是在 append 落盘的途中才暴露的** —— 那时已经下了大半本，
用户只看到一句莫名其妙的 IO 异常。

现在下载前估算体积并检查目标盘，不够就提前警告并让用户决定要不要继续。
**查不出来时一律放行**（网络盘、权限受限），绝不因为"算不出空间"就不让用户下载。

### 12.7 其它

- **移动版域名可配置**（`站点配置.ini` 的 `mobilehost`）。原来是 `const`，运行时改不了；
  实测踩到域名被拒时，用户只能改代码重编译。现在改一行配置就行。
- **EPUB 补 `dc:date`**：EPUB3 只要求 `dcterms:modified`，
  但 Calibre / KOReader 按 `dc:date` 显示"更新于"并据此排序，缺了它书架里那一列是空的。
- **`DirCache` 共享读**：缓存可能正被另一个进程写（界面在预抓、同时命令行工具在读），
  `File.ReadAllText` 默认只允许共享读，会直接抛"文件正由另一进程使用"。
  现在用 `FileShare.ReadWrite` 打开并重试。
- **CI 加了每周定时联网冒烟**（`live-smoke` job）：`continue-on-error: true`，
  站点临时故障不该卡 PR，它的作用是"尽早发现站点改了"。
  同时把 `_e2e.exe` 加进了 build 门禁，并把 `_e2e` / `_liveprobe` 的 csproj 补上
  （否则 CI 编不出来 —— v1.0.2 就因为"只在 build.bat 里加了文件"而红过）。

### 12.9 目录遍历断点续爬

PC 版遍历 774 章实测要 **~2 小时**，而原来的实现把进度攒在内存里 ——
中途关掉程序（或崩一次）就**整本重来**。对两小时的任务来说这是最难接受的一种失败。

**为什么可以安全续**：遍历链是**确定的** —— 从最后一章出发，每页的「上一页」
链接（`var uiiekp0do`）都唯一指向前一页，直到回到目录页。
所以只要记下"上次走到哪一页"，从那里接着走就行，不会错位。

实现（`CrawlResume.cs` + `BiqugaSite.CrawlChapters`）：

- **落盘时机**：每 50 页 **或** 每 45 秒（双条件）。只按页数不够 ——
  站点限速时 50 页可能要十几分钟，那就跨得太久了。
- **存什么**：当前页 key、起始页 key、目录、**已收录章节的 id + 标题**、已走页数。
- **不存正文**：正文体积大，而续爬后重新走的那段只为拿到更靠前的章节，
  正文会在下载阶段按需再抓。把正文也存进去会让断点文件涨到几十 MB。
- **走完就删**：遍历正常结束会 `Clear()` 掉断点，否则下次会"续"到一份走完的断点白跑一趟。
- **失效保护**：`StartKey` 对不上（换了书/换了源）就作废这份断点。
  这一条是关键 —— 如果校验不严，A 书的断点被 B 书用上，
  **能把 A 的章节拼进 B 的目录里**，那比"重走一遍"糟糕得多（重走只是慢，拼错是数据损坏）。

界面：点「刷新目录」时，如果这本书有断点，会问一句
「接着上次走（省时间）」还是「从头重新遍历（目录最完整）」。
**让用户选而不是自动续**：续爬省时间，但从上次位置接着走意味着
如果站点这期间改了目录，拿到的会是新旧拼接的结果 ——
而用户自己知道自己是"昨天没爬完"还是"想要最新目录"。

验证（`TestCrawlResume` + `TestResumeBoundary`，共 32 条断言）：

- 断点存取往返（含**标题里带引号**这种手工拼 JSON 最容易错的输入）
- **换书后断点必须作废**（`StartKey` 不匹配）
- 损坏文件降级为 null、不抛异常
- ★ **边界正确性**：用可控模拟链（100→99→…→1）走两遍 ——
  一次走完当基准，一次走到第 40 页落断点后中断、再从断点续完，
  比对**章数一致、不缺章、不重复章、边界页只出现一次**。
  这一条专抓"断点语义错一位"，那种错会悄悄让目录少一章或多一章而不报错。

## 十三、还没做的（更新版）

对比同类工具后**明确不做**的：

| 不做 | 理由 |
| --- | --- |
| **配置化书源规则引擎** | 同类工具（so-novel 8.3k star）靠这个活得很好，但它的前提是"软件不提供内容，也不提供任何规则"。本项目 `SiteProfile.cs` 里有一道**明确的合规闸门**（`ForbiddenKeys`：selector/xpath/regex/rule/@js…），这是**有意的设计边界**，不是缺失的功能 |
| **绕验证码 / 破解付费章节** | 直接越过合规红线 |
| **字体反混淆** | `fanqienovel-decryptor` 的作者自己说"解密了字体也拿不到全文（还有验证码和阅读权限）"，ROI 极低 |
| **Web UI / Docker** | 与"免安装单文件 exe"的核心卖点冲突 |
| **PDF / MOBI / AZW3** | MOBI/AZW3 需要外部工具，PDF 排版效果差；有 EPUB + Markdown 两个出口就够了 |

# 界面布局（为什么这么排 + 怎么验证）

这个文件记录一次真实的用户反馈、根因、修法，以及**怎么让这类问题不再复发**。

## 一、用户反馈

> 有用户反映界面有布局问题，说这一条文字看不清

截图里能看出：章节栏那排按钮**超出了面板宽度**（最右边「设置/安装」被截断），
而 `（还没载入目录）` 那个状态文字被「打开保存目录」按钮**盖住**了。

## 二、根因（用探针量出来的，不是猜的）

老代码里所有控件的 `Location` 都是硬编码坐标，于是有三个必然出问题的点：

| # | 问题 | 实测证据 |
| --- | --- | --- |
| 1 | 按钮总宽超过面板可用宽 | 最右按钮 `x=876 + 宽 140 = 1016`，而面板只有 984 → **被切掉 32px** |
| 2 | 状态文字与按钮坐标区间重叠 | 文字 `x=606`，而 `x=700` 的按钮正好压上来 → **交集 10x17** |
| 3 | 假水印是独立控件，按坐标摆 | `Label('粘贴番茄书籍链接或 book_id')` 与 SplitContainer **交集 167x17** |
| 4 | 「设置」按钮压在「离线模式」复选框上 | **交集 84x22**（比用户报的那处更严重，只是他们没注意到） |

## 三、修法

### 1. 坐标硬编码 → 用 Dock 排

- 每一行用 `FlowLayoutPanel`（`WrapContents=false`、`FlowDirection=LeftToRight`）：
  子控件按内容宽度依次排开，**不可能互相重叠**
- 输入框 / 状态文字用 `Dock=Fill` 吃掉剩余宽度：窗口拉宽不留空白，拉窄自动缩
- 状态文字开 `AutoEllipsis`：窗口极窄时显示「…」，**不会去压按钮**
- 按钮宽度全部来自实测文字宽度（`TextRenderer.MeasureText`）+ 内边距，见下表

| 文字 | 实测宽 | 按钮宽 |
| --- | --- | --- |
| 搜索 | 32 | 40 |
| 载入目录 / 刷新目录 | 56 | 64 |
| 浏览器搜索 | 68 | 76 |
| 全选 / 反选 / 取消 | 32 | 44 |
| 全不选 | 44 | 56 |
| 下载全部章节 / 下载选中章节 / 打开保存目录 | 80 | 92 |
| 用第三方工具下载 | 104 | 112 |
| 设置核心 | 72 | 72 |

### 2. 顶部拆成两行（番茄模式三行）

一行放不下（站点 216 + 书名 276 + 四个按钮 303 = 795，最小窗口可用宽只有 780），
所以：常用操作两行常显，**番茄专用的「浏览器搜索 / 用第三方工具下载 / 设置核心」整行隐藏**，
切到番茄站才出现（隐藏时顶部面板自己收高度，不留空行）。

### 3. 假水印 → 系统原生水印

老实现是在窗体上摆一个灰色 `Label` 冒充水印，它和其它控件抢坐标。
现在用 `EM_SETCUEBANNER`（Vista+ 的提示横幅），由输入框自己绘制，**不产生任何额外控件**，
从根上不可能再遮挡。

### 4. 缩放模式：Font 而不是 Dpi

控件宽度是写死的数字，`AutoScaleMode.Dpi` 只缩放窗体尺寸、不缩放这些数字，
在 125% 缩放的机器上按钮文字会被切掉。改成 `AutoScaleMode.Font`，
按字体比例缩放**所有**尺寸（含控件宽高）。

### 5. z-order：Dock=Fill 必须压到最底

`split.SendToBack()`。之前写的是 `BringToFront()`（反了），
只是恰好因为顶部面板更宽才看起来正常 —— 一旦顶部变矮，整个搜索区就被 split 盖没。

## 四、怎么保证不再复发

### 1. `tools/LayoutProbe.cs`（量尺寸 + 截图）

```bat
dist\_layoutprobe.exe                      :: 3 个站点模式 × 4 种窗口尺寸，只量不截图
dist\_layoutprobe.exe --shots 820 600      :: 顺便把界面截成 PNG（会短暂抢一下焦点）
dist\_layoutprobe.exe 900 660 1200 800     :: 指定窗口尺寸
```

输出的 `dist\_layout.txt` 会列出每个控件的坐标，并把**越界**和**同层重叠**逐条报出来，
每条都给出"右边被切掉多少 px / 大约几个字看不见"。退出码 0 表示没问题。

两个踩坑记录（都写进代码注释了）：

- **不要用 `DrawToBitmap` 验证界面**：它走 WM_PRINT 路径，画出来的东西和真实绘制不一致
  （实测顶部面板整块不见、三种站点模式的图字节完全相同）。要验证"用户看到什么"只能截屏。
- **截图前要把窗口提到最前**：`SWP_NOZORDER` 不改变 z-order，截出来会混进盖在上面的别的窗口。

### 2. 离线单测里的布局断言（CI 每次都跑）

`tests/OfflineTests.cs` 的 `TestLayout()`：

- 先**自证检查器有效**：故意摆两个重叠控件 + 一个越界控件，必须都能报出来
  （否则"布局无越界"可能只是因为检查器永远返回空）
- 再对 **3 种窗口尺寸（820x600 / 1000x720 / 1280x800）× 3 个站点模式** 各建一个真实窗体
  （屏幕外、无弹窗），断言没有任何控件越界或互相重叠

一共 11 条断言，含在 `dist\_offlinetests.exe` 里 —— 改界面时只要跑一次单测就能发现回归。

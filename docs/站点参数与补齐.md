# 站点参数 / 缺章补齐 / 断点续传 / Markdown 导出

这四个功能是看了同类工具之后加的（调研见 `docs/同类工具调研.md`）。
其中「缺章补齐」和「断点续传」共用同一套底层能力：**在文件里定位到具体的某一章**。

---

## 一、站点参数（`站点配置.ini`）

程序第一次启动会在 exe 旁边生成 `站点配置.ini`，用记事本就能改：

```ini
[biquga-m]
displayname=笔趣阁（移动版·快）
workers=8            # 并发线程数
mindelayms=60        # 请求间隔（随机区间）
maxdelayms=180
timeoutseconds=25
maxretries=3
outputencoding=utf-8 # 或 gbk（老设备/老阅读器需要）
useragent=           # 留空 = 用内置的 Chrome UA
```

### ⚠️ 这个文件**只接受"怎么连接"的参数**

**明确拒绝**选择器、正则、XPath 这类"内容怎么提取"的键（`selector` / `regex` / `xpath` /
`rule` / `提取` / `规则` …）。命中就会被忽略，并在界面日志里说明原因。

原因不是技术限制，而是边界：**内置或分发"书源规则"等于分发内容源**，
那是本工具不碰的红线（同类工具里活得最久的 so-novel 也是这个立场 ——
"软件不提供内容，也不提供任何规则"）。这条拒绝逻辑有断言守着。

### 改参数能解决什么

| 症状 | 怎么改 |
| --- | --- |
| 正文变成"访问太频繁了" | `workers` 调小（比如 3），`mindelayms`/`maxdelayms` 调大 |
| 下载太慢、站点没限速 | `workers` 适当调大（别超过 16） |
| 老阅读器打开是乱码 | `outputencoding=gbk` |

**实测**：`outputencoding=gbk` 会让 txt 用 GBK 写（不写 BOM），体积也更小
（中文 2 字节 vs UTF-8 的 3 字节）；表头、正文、收尾的原位改写都跟着这个编码走。

## 二、缺章补齐

站点上有些章本身就是空的（"正在手打中，请稍等片刻"），整本下完中间会留几个洞。
点 **「补齐缺章」**：

1. 扫描文件，列出**缺失或空掉的章节**
2. 只重新抓这几章
3. 按目录顺序**插回正确位置**（不是追加到末尾）

已有的正文一个字都不会动 —— 这条有断言守着（表头区字节数不变、旧正文前缀一致）。

### 靠什么定位到"某一章"

v1.0.5 起，txt 里每一章前面多了一行锚点：

```
<!--c:44302617-->
第一章 天黑别出门
---------

正文…
```

它是 HTML 注释：阅读器/编辑器不显示、正则清洗不会误删，但让程序能**按 id 精确定位**。
这也是为什么**旧文件不支持补齐** —— 没有锚点就只能靠标题字符串猜位置，猜错会把正文插错地方，
所以程序宁可明确拒绝并提示你重新下载，也不冒险。

## 三、章节级断点续传

下载中途关窗口/断网是常事（1000 章要十几分钟）。续传的做法和补齐**完全一样**：
找出文件里没有的章，只抓那些，插回正确位置。

所以操作上很简单：**重新点「下载全部」或「补齐缺章」都行** ——
程序不会重下已有的章，只会补缺口。实测：下到第 4 章中断，再跑一次只下剩下的 6 章。

## 四、Markdown 导出

点 **「导出 Markdown」**，生成 `书名.md`：

- 开头是 **YAML front matter**（title / author / source / exported / chapters）——
  pandoc、Hugo、Jekyll 都认
- 自动生成**带锚点的目录**（`<a id="ch0001">`，GitHub / Typora / VS Code 都能跳转）
- 章节是 `##` 二级标题，正文按段落排
- **正文里的 markdown 语法字符会被转义**：`# 开头`、`- 开头`、`2. 开头` 这些
  会被加上反斜杠，否则章节能把整篇文档的结构搞乱（有断言守着）

用途：`pandoc -o 书名.epub 书名.md` 转电子书、丢进 Obsidian/Logseq 做笔记、
用 Typora 导出 PDF。

## 五、四个功能的实测验证

| 功能 | 验证 |
| --- | --- |
| 站点参数 | 手改 ini → 并发/间隔/超时/重试/UA/编码逐项生效；越界值被夹住；损坏文件回退默认；**含提取规则的键被拒绝并说明原因** |
| 缺章补齐 | 造一个缺第 3/4/8 章的文件 → 补齐后 10 章齐全、顺序正确、老正文前缀一致、表头统计与进度标记同步更新；再点一次不重复下载 |
| 断点续传 | 下 4 章后中断 → 再跑只下剩余 6 章，最终 10 章齐全、顺序正确 |
| Markdown | YAML 头、目录锚点、章节标题、段落、行首语法字符转义、空章/分卷行跳过、无正文时明确报错 |

离线单测总数：**484 项**（v1.0.4 是 273 项）。
